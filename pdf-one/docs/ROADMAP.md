# ロードマップ

目標は Acrobat（Pro）。**社内の人が Acrobat でしていることが、PDF One で全部できる** 状態を 1.0 とする。画面は [UX.md](UX.md) に従い、どの版も「説明なしで使える」（UX §11）を通してから出す。版の中身と順番は仮に置いたもので、利用者と相談して決める（0.1 と同じ。2026-10-13）。

## 1. 考え方

- **器を先に、機能はその後**。0.2 で画面を「見るアプリ」から「編集するアプリ」に作り直す。機能を足す前に器を変えないと、足すたびにアイコンが増えて分かりにくくなる
- **使う頻度の高い順**。社内で多いのは、印鑑・記入・ページの抜き差し・つなげる・小さくする・印刷。文字の修正と黒塗りは回数は少ないが「できないと Acrobat を待つ」ので早めに
- **元のファイルを壊さない**（0.1 からの方針）を、文字の編集や黒塗りでも守る
- **通信しない**（アップデートの確認だけ）。電子署名のタイムスタンプのように通信が要るものは、相談してから
- 期間は置かない。各版の **完了条件** で区切り、出してから次の版の順を決める。規模は 小 / 中 / 大 で示す

### 0.2 編集するための画面（規模：中）

**目的**：機能を足す前に、器を「編集するアプリ」にする。使う頻度の高い小さな機能（印刷、記入、印鑑）もここで。

入れるもの：

- UX §4〜§10 の画面：作業タブと絵＋言葉の道具、右の「詳細」、案内と状態の行、OS に合わせたテーマ、14px と「文字を大きく」、言葉の総入れ替え（UX §3）、1 回置いたら「選択」へ
- スタート画面（1 ページ目の絵、使い方）、初回の案内、「何をしますか」、アプリの中の使い方
- 保存の前に「新しいファイル / 上書き」を聞く。下書きの自動保存と復元
- 開いたときの案内（画像だけ、入力欄あり、保護、署名あり）
- **印刷**：範囲、用紙に合わせる、1 枚に 2 ページ、ページの向き。両面や部数は OS のダイアログに任せる
- **入力と署名**：記入（枠なし・白い塗りの文字。入力向けの既定）、✓ ✗ ● 線、日付、署名（ペンで書いた線をライブラリに入れる、ライブラリから置く）
- **印鑑**：日付印（名前・日付・丸枠・赤）、文字の印、ライブラリの整理（名前、並べ替え）
- 消しゴム、回転して見る

技術メモ：

- 道具はコマンド表（`lib/commands.ts`）を指すだけにし、タブの表（`lib/ribbon.ts`）と案内の文（`lib/hints.ts`）を足す。メニューバーとショートカットは今の仕組みのまま
- 印刷は、pdf.js でページを画像に描き（200〜300 dpi、書き込みも重ねて）、印刷用の文書を組んで WebView の印刷に渡す。Windows（WebView2）と macOS（WKWebView）の両方で確かめる。印刷ダイアログが出ない・画質が足りないときは、Rust から OS の印刷（Windows は XPS、macOS は `NSPrintOperation`）に切り替える。保存した PDF をそのまま OS に渡す案は、既定のアプリ（Edge など）に依存するので取らない
- 下書きは store の文書（ページの並び、書き込み、入力した値）を JSON にし、元のファイルの場所とハッシュと一緒に `drafts/` へ。復元は元のファイルが同じときだけ
- 日付印と文字の印は、画像ではなく Rust で見た目を描く（拡大してもきれい、文字を変えられる）
- テーマは `index.css` のトークンを `prefers-color-scheme` で切り替える。Platform UI §1 からの逸脱なので ADR-0002（判断 2）

完了条件：UX §11 の代表タスク 1〜6 を合格。Windows の 3 機種（うち 1 台は 1366 × 768・125%）と macOS で印刷できる。`npm test`、`npm run lint`。

### 0.3 文字と画像を直す（規模：大）

**目的**：「1 文字直したいだけなのに Acrobat の順番待ち」を無くす。この計画で技術的に一番難しいところ。2 段階で進める。

入れるもの：

1. **白で消して上から書く**：範囲をドラッグ → ページの背景色で塗りつぶし、文字を置く枠がすぐ出る。どの PDF でも効く逃げ道
2. **もとの文字を直す**：「文字と画像」タブで文字をクリック → 行の枠が出て、その場で打てる。同じ行の中で足す・消す・変える。行が長くなれば右へ伸びる（段落の折り返しは 0.4）。直せない文字は「この文字は直せません。白で消して上から書いてください」と案内し、1 の道具に渡す
3. **画像**：クリックで選ぶ、動かす、大きさ、削除、差し替え（ファイル、貼り付け）、切り抜き
4. ヘッダー・フッター、ページ番号（位置、書式、最初の番号、範囲、見本）。透かし（文字 / 画像、斜め、濃さ、範囲）、背景の色
5. ページの複製・差し替え・余白を切る。吹き出し。文書の情報の編集

技術メモ：

- ページのコンテンツストリームを Rust で読み（lopdf の `content::Content`）、文字を描く命令（Tj / TJ）と画像（Do）を、pdf.js が画面に出している文字・画像の位置と突き合わせる。画面で選んだ文字 → 何番目の命令の何文字目か、を決める表を `open_pdf` のときに作る
- 文字の変更は、その命令だけを書き直す。字形は、埋め込みフォントにあればそれを使い、無ければ OS のフォント（`font.rs`）で新しいフォント資源を足して置き換え、「游ゴシックで書きます」と知らせる。縦書き、アウトライン化された文字、Type3 は直せない文字として扱う
- 「白で消す」はページのコンテンツに描く（書き込みだと、ほかのビューアで消せてしまう）。保存のとき Form XObject として追記する
- 画像の差し替えは `image.rs`。切り抜きはクリップで
- ヘッダー・フッター・透かしは `compose.rs` で各ページのコンテンツの前後に足す。フォントは `font.rs`
- 1 と 3〜5 を先に出し、2 は PDF の構造が多様なので、社内でよく使う PDF（Word から出したもの、複合機のスキャン、会計システムの帳票）で試しながら範囲を広げる

完了条件：社内の代表的な PDF 20 本で、文字の修正が「直せる」か「直せないと案内する」のどちらかになり、保存した結果を Acrobat・Edge・プレビューで開いて崩れない。UX §11 に「文字を 1 か所直す」を足して合格。

### 0.4 作る、つなげる、変換する、読み取る（規模：大）

**目的**：PDF の前後の仕事（Word から作る、まとめる、送れる大きさにする、スキャンを探せるようにする）を PDF One で済ませる。

入れるもの：

- **つなげる**（ウィザード）：ファイルを並べる（PDF、画像、Word・Excel・PowerPoint）、ドラッグで順番、「1 つにする」→ 新しいタブ。スタート画面の「新しく作る」からも
- 画像から PDF（用紙、向き、余白）。白紙の PDF
- Word・Excel・PowerPoint から PDF：Windows は入っている Office の「PDF として保存」を COM で呼ぶ。Office が無い PC では「Word で PDF に保存してからつなげてください」と案内
- **小さくする**：3 段階（きれい / ふつう / 最小）、前後の大きさを見せてから実行。画像の縮小と再圧縮、使われていないものの削除、重複したフォントの統合
- **文字を読み取る**：Windows は Windows.Media.Ocr、macOS は Vision（0.1 の方針どおり、OS の機能だけ）。透明な文字の層を重ね、検索・コピー・マーカーが効くようにする。言語は日本語と英語。進み具合と中止。精度は OS 次第と明記
- 変換：PDF → 画像（ページ、解像度）、文字（テキスト）、Word（段落・見出し・画像・簡単な表。docx は Rust で組む）
- 段落として直す（折り返し）。リンクとしおりの作成・編集。用紙をそろえる

技術メモ：

- Office の COM は Rust の `windows` クレートか PowerShell。Excel は印刷範囲、PowerPoint はノート無しを既定に
- OCR の Windows 日本語は OS の言語パックが要る（判断 5）
- PDF → Word は「見た目の再現」を狙わず、文字と段落と画像を取り出して Word で直せる形にする。Acrobat ほどにはならないと最初から伝える

完了条件：UX §11 に「2 つの PDF と Word を 1 つにつなげる」「メールに添付できる大きさにする」を足して合格。スキャン PDF 10 本で検索が効く。

### 0.5 守る（規模：中）

**目的**：社外に出す前の処理（黒塗り、パスワード）と、署名された PDF の扱い。

入れるもの：

- パスワードをかける（開く用、印刷・コピー・編集の制限用。AES-256）。外す（知っている場合）。かけた PDF を PDF One で開いて編集できるようにする（今は表示だけ）
- **黒塗り**：範囲をなぞる、または「検索して黒塗り」（氏名、電話番号）→ 赤い枠で印 → 「黒塗りを確定」で本当に消す。確定は戻せないので、確定の前に説明し、確定後は自動で別名保存
- 隠れた情報を取り除く：文書の情報、書き込み、添付、JavaScript、しおり、使われていないもの。項目ごとにチェック
- 署名を壊さない保存：署名済みの PDF に書き込んで保存しても署名が有効なまま（増分更新）
- 電子署名：検証（誰が、いつ、その後の変更の有無を表示）。付ける（PFX、Windows の証明書ストア、macOS のキーチェーン。見える署名欄に名前と日付）

技術メモ：

- 暗号化は lopdf の対応を確かめ、足りなければ AES-256（R6）を自前で
- 黒塗りは、文字は該当の文字を Tj / TJ から取り除き（0.3 の対応表を使う）、画像は該当の画素を黒く塗って再エンコード、ベクターはクリップ。範囲にかかる書き込みとリンクも消す。確定後に文字の層を読み直して残っていないことを自動で確かめる
- 増分更新は、lopdf が全体を書き直すので、追記の書き出しを自前で持つ（0.1 のロードマップに書いたとおり）。電子署名の付与もこの上に載る（ByteRange、PKCS#7）
- タイムスタンプ（RFC 3161）と失効の確認（OCSP）は通信が要る（判断 4）

完了条件：黒塗りした PDF から、文字の層・画像・メタデータに元の文字が残っていないことを自動テストで確かめる。署名済み PDF（Acrobat で署名したもの）に書き込んで保存し、Acrobat で署名が有効なまま。UX §11 に「名前を黒塗りする」「パスワードをかける」を足して合格。

### 0.6 やり取り、入力欄を作る、比べる、まとめて（規模：大）

### 1.0 仕上げ（規模：中）

- 全機能で UX §11 を合格。Windows 3 機種と macOS 1 機種
- 性能の目標：1,000 ページ・500 MB の PDF で、開く 3 秒以内、ページの描画 100 ms 以内、保存 10 秒以内
- 署名付きの配布（Microsoft と Apple の署名。インストールの警告を無くす。判断 6）
- 利用者向けの 1 枚の説明と、社内への案内

## 4. 大きな判断（相談して決める）

| 6 | **コード署名**（Microsoft Authenticode、Apple Developer）の費用と手続き | 1.0 の前 |
| 7 | **スキャナー連携**（WIA / ICA）が要るか。複合機から共有フォルダへスキャンしているなら不要 | 0.4 の後 |
| 8 | **0.3 と 0.4 の順番**。文字の修正と、つなげる・小さくするのどちらを先にするか | 0.2 の利用者テストで聞く |

## 5. 進め方

各版で同じ流れ。

1. [SPEC.md](SPEC.md) にその版の振る舞いを足す（画面の言葉は UX §3 で確かめる）
2. 実装。Rust の PDF 処理はテストを同じファイルに、コマンドは `lib/commands.ts` に、モックも同じ PR で（[CLAUDE.md](../CLAUDE.md)）
3. `examples/sample.rs` で作った PDF を Acrobat・Edge・プレビューで開いて確かめる
4. 利用者テスト（UX §11）→ 直す
5. リリース（README「リリース」）。CHANGELOG の変更点は利用者の言葉で
6. 使ってもらい、次の版の順番を決める。[ARCHITECTURE.md](ARCHITECTURE.md) と [project-context.md](../decisions/project-context.md) を更新する
