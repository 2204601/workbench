# ADR-0003：文字の修正では、ページの中身を書き換える

- 状態：採用
- 日付：2026-10-14
- 対象：`docs/SPEC.md` §1「ページの中身（コンテンツストリーム）は書き換えない」

## 背景

- 0.1・0.2 は、書いたものをすべて PDF の標準の注釈として保存してきた。どのビューアでも同じに見え、Acrobat で続きを直せ、元のページには触れない
- 「ページにもとからある文字を直したい」という要望が来た（0.3 の中心、`docs/ROADMAP.md`）。注釈では、もとの文字が下に残る。白い四角で隠すだけだと、ほかのビューアで四角を消せば読めてしまい、文字の検索やコピーにも出る。直したことにならない
- したがって、もとの文字を描いている命令を取り除くには、ページの中身そのものを書き換えるしかない

## 決定

- 文字の修正（`AnnotKind::Edit`）だけは、保存のときにページの中身を書き換える。それ以外の書き込みは、これまでどおり注釈
- 書き換えは `src-tauri/src/pdf/textedit.rs`。もとの行を描いていた命令（`Tj` `TJ` `'` `"`）は、**何も表示せず、文字の位置だけ同じ距離進める**命令に置き換える。あとに続く文字は動かない。新しい文字は、ページの最後に、同じ位置・大きさ・色で描く。もとの行のフォントが書ける文字（コードから文字への対応を逆に引く）はそのフォントで、書けない文字だけアプリが埋め込む日本語フォントで描く
- 直す対象にするのは、文字の情報を読み戻せて、位置を確かめられる行だけ（Identity-H の CID フォントと、幅の分かる単純なフォント。横書きで、斜めでない）。ほかは「直せない」と理由を返し、画面で「文字を置く」を案内する。位置が確かめられない行は、書き換えない
- インライン画像のあるページは、ページの中身を読み戻して書き直すと壊れるおそれがあるので、直せない
- ページごとに新しい内容ストリームを作る（同じページを 2 回使っていても、互いに影響しない）。元のファイルは書き換えない（保存の決まりは変わらない）
- 直した行は、保存したファイルの中では普通の文字。開き直しても「直した行」としては出ない（元に戻すのは保存前だけ）

## 影響

- Acrobat や Edge でも、新しい文字はふつうの文字として選べて、検索に出る。もとの文字はファイルから消える（検索にも出ない）。字の形は、もとのフォントにある文字ならそのまま。もとのフォントに無い文字だけ日本語のフォントになる
- 新しい文字がもとより長いと、まわりの内容に重なることがある（画面では見えるので、そのとき直す）
- 当初は、フォントをすべて日本語のフォントに替えていた（0.2.2）。利用者から「フォントが変わってしまう」と言われ、もとのフォントを使うようにした（0.2.3）。使った文字だけを埋め込んだフォントには、ページに無かった文字の字形が無いので、その文字だけは日本語のフォントで補う。字形を足すフォントの書き換え（サブセットの拡張）は、まだしない
- 実物の PDF での確認は、Chromium と LibreOffice から出した PDF で行った。社内の代表的な PDF（Word、複合機のスキャン、会計システムの帳票）での確認は、利用者に試してもらう（ROADMAP 0.3 の完了条件）
